# Localization guide

The interface language (`settings.uiLanguage`) is independent of the course. Strings live in `src/i18n`.

## Using translations

```tsx
import { useI18n } from '../i18n/react';

function Example({ count }: { count: number }) {
  const { t, formatNumber } = useI18n();
  return <p>{t('dashboard.dueAndNew', { due: count, new: 3 })}</p>;
}
```

- **Never write UI text inline** – not in JSX, not in `aria-label` / `title` / `placeholder`, and not as `lang === 'zh' ? … : …`.
  `npm run check:i18n` fails when a file has more hardcoded strings than the baseline.
  Text that is not language (brand names, code) can carry an `i18n-ignore` comment.
- **One key per sentence.** Never build sentences from pieces (`t('a') + n + t('b')`): word order differs between languages.
  Use placeholders: `"{streak}-day streak"`.
- **Plurals** use ICU syntax: `"{count, plural, one {# card} other {# cards}}"`. The plural categories of each language come from `Intl.PluralRules`, so
  translators only write the forms their language has (Chinese: `other` only).
- **Numbers and dates** go through `useI18n().formatNumber / formatDate`, never `toLocaleString('en')`.
- Keys are typed (`MessageKey`): a typo fails `npm run typecheck`. Dynamic keys must be a union of literal keys.
- Course *content* (grammar lessons, vocabulary glosses) is not UI chrome. It follows the course, with a fallback chain, and is not translated through these tables.

## Files

```
src/i18n/
  types.ts            LOCALE_META (languages, native names), UiLanguage
  format.ts           message syntax: {variables} and plurals
  index.ts            lookup with fallback chain (lang → English), lazy language packs, detection, Intl formatters
  react.tsx           I18nProvider, useI18n, useLoadedLanguage, useDocumentLanguage
  locales/en/*.ts     source of truth, one file per area (as const)
  locales/zh/*.ts     must be complete – tsc fails when a key is missing
  locales/de/*.ts     may be partial – missing strings fall back to English
```

## Adding a language

1. Add it to `LOCALE_META` in `types.ts` and a loader to `loaders` in `index.ts`.
2. Create `src/i18n/locales/<code>/` with the same file names as `en` (copy `de` as a template) and an `index.ts` that spreads them.
3. Translate. Untranslated keys fall back to English; `npm test` verifies that placeholders match the English source.
4. Run the app with the new language and check layouts at 360 px width (long languages wrap; see `e2e/layout.spec.ts`).

## Language selection

Saved choice → browser language when it is a supported non-English language (first run only) → the course default
(`CourseConfig.defaultUiLanguage`; the English course is built for Chinese speakers). The pack of the chosen language is loaded
before the first screen is shown; switching language keeps the old language on screen until the new pack is ready.

## More building blocks

- **Rich text**: `rich('key', vars, { b: (text) => <b>{text}</b> })` for messages like `"<b>{n}</b> due"`; translators move the tags freely.
- **Data-driven keys**: `tx('badge.<id>.title', fallback)`; `levelLabel(level, course, t)` for exam-based level names.
- **Errors**: throw `new LocalizedError('errors.x.y', vars)`; show with `errorText(t, error)` / `describeMessage(t, message)`.
- **Pseudo-locale**: run the dev server and open `/?lang=xa#/home` – every string is accented, ~35 % longer and bracketed; plain English text means a string was not translated.
- **Checks**: `npm run check:i18n` (hardcoded text, must be 0), `npm test` (key/placeholder/tag parity, badge coverage), `e2e/smoke.spec.ts` (no raw keys on screen), `e2e/layout.spec.ts` (no overflow in en/de/zh/xa at 360/768/1280 px).
